DTR Sandbox

Three live scenarios, each a real client and a real authorization server exchanging actual HTTP requests. Pick one to see the deferred-token flow with its own request/response detail and a color-coded log of both sides.

interaction_required

ID-JAG, human interaction required

A client presents an identity assertion (ID-JAG) the authorization server can't act on alone — it hands back an interaction_uri and the client routes a human there.
authorization_pending, no interaction_uri

client_credentials + Rich Authorization Requests

A machine client requests a specific resource with no user in the grant at all — there's no one to route an interaction link to. Resolution happens on the AS's own console.
authorization_pending, dual AS views

Fraud review after an already-granted consent

An end user already approved a transfer via the ordinary Authorization Code flow — but a separate fraud reviewer, not the end user, must additionally sign off before the token issues.
